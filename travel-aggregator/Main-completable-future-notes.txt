import java.util.concurrent.CompletableFuture;

// how Thread.currentThread() works
// The Mechanism: When you call Thread.currentThread(), Java looks at whichever thread is currently executing that specific line of code and returns that specific Thread object.
// The Chain: Once you have that object, you can immediately call its instance method, .getName(), to see its name.
// What Java does behind the scenes:
// Thread current = Thread.currentThread(); // Gets the active thread object
// String name = current.getName();        // Gets its name ("main", "worker-1", etc.)
public class Main2 {

    public static double fetchFlightPrice() {
        try {
            Thread.sleep(2000);
        } catch(InterruptedException e) {
            System.out.println("[" + Thread.currentThread().getName() + "] Fetched flight price");
            return 400.0;
        }
    }

    public static double fetchHotelPrice() {
        try {
            Thread.sleep(1500);
        } catch (InterruptedException e) {
            System.out.println("[" + Thread.currentThread.getName() + "] Fetched hotel price");
            return 250.00;
        }

    }



    public static void main(String[] args) {
        long startTime = System.currentTimeMillis();

        CompletableFuture<Double> flightFuture = CompletableFuture.supplyAsync(() -> fetchFlightPrice());
        CompletableFuture<Double> hotelFuture = CompletableFuture.supplyAsync(() -> fetchHotelPrice());

        // when you chain .thenCombine(), you are setting up an event listenenr. You are telling the JVM:
//             Wait for flightFuture to finish its background work.
// Wait for hotelFuture to finish its background work.
// The moment both are done, take the resulting numbers (400.00 and 250.00) and automatically inject them into the variables you named in your lambda: (flightPrice, hotelPrice).
// You don't need to manually store them in variables beforehand because CompletableFuture acts as the container holding those values until they are ready.
        CompletableFuture<Double> combinedFuture = flightFuture.thenCombine(hotelFuture, (flightPrice, hotelPrice) -> {
            double total = flightPrice +  hotelPrice;
            System.out.println("Total package price: $" + total);
            return total; //we return total because the lambda function inside .thenCombine() has its own return type, which is completely independent of the main methods vois return type.
        }

//🔍 Breaking Down the Return Chain
Here is exactly why that return total; matters:
1. The Lambda Contract
The .thenCombine() method expects you to provide a function that takes two inputs and outputs a new result. Because you specified CompletableFuture<Double> combinedFuture, the lambda function inside must return a Double.
2. Passing the Torch
If you don't return total, the combined future doesn't know what its final value is supposed to be. Returning total hands that value over to combinedFuture so you can use it later in your program.


💡 What happens if you don't return?
If you try to remove return total;, your code will fail to compile. The Java compiler will complain that you are trying to provide a function that returns nothing (void) when it explicitly requires a function that returns a Double.
Shortcut: Implicit Returns
